# PhotoPicker 仕様

Sony α で JPG + ARW を同時記録した写真を、高速に選別する macOS アプリ（SwiftUI）。
メタデータの調査結果は [メタデータ調査.md](メタデータ調査.md) を参照。

最終更新: 2026-09-29（拡大表示・連写の区切り方・ARW だけのファイル・設定画面を追記）

## 目的

- 1回あたり 1,000〜5,000 枚を、待たされずに選別する
- 連写はグループにまとめて、その中から良いコマを複数選ぶ
- 不要な写真は JPG と ARW をまとめて `_rejected` フォルダへ移す

## 決定事項

| 項目 | 決定内容 |
|---|---|
| プラットフォーム | macOS 26 以上、SwiftUI |
| 入力 | Mac 内のフォルダを開く（ドラッグ&ドロップ可）。SD カードからの直接読み込みは対象外 |
| 表示対象 | JPG と、ペアの JPG がない ARW。JPG と同じ名前の ARW は「ペア」として判定と移動に連動させる（詳しくは「ARW だけのファイル」） |
| 判定 | 採用 / 不採用 の2値（★レーティングは使わない） |
| 連写 | Sony MakerNote の `SequenceNumber` とファイル番号でグループにまとめる。グループ内で複数枚を採用できる |
| 連写以外のグループ化 | しない（インターバル撮影や、近い時刻の単写はまとめない） |
| 未判定の扱い | 連写グループでは、採用しなかったコマを不採用とみなす。1枚も採用しなかったグループは全コマを移す（警告は出さない）。単写では、不採用の印を付けたものだけを移す |
| 移動のタイミング | 選別中は印だけ付ける。最後に「適用」で一括移動する |
| 移動先 | 開いたフォルダの中の `_rejected/` |
| 画面構成 | 大きなプレビュー＋下にフィルムストリップ |
| 拡大表示 | 全体表示・100%・200% と、ピンチによる自由な倍率。Z ではソニーのフォーカス位置を、クリックではその点を拡大する。グループ内でコマを移っても、同じ位置・倍率を保つ（詳しくは「拡大表示」） |
| フォーカス枠 | 通常表示・拡大表示のどちらでも、フォーカス位置に枠を描く。⇧F で表示を切り替える |
| 判定後の送り | 採用・不採用の印を付けたら、自動で次のコマへ進む |
| 判定の色 | 採用は緑、不採用は暗く表示する |
| キー操作 | Lightroom 風（下表） |
| 設定画面 | あり（⌘,）。先読み枚数などを設定する（詳しくは「設定画面」） |
| 途中保存 | フォルダ内の `.photopicker.json` に自動保存し、次に開いたとき続きから再開する |
| メタデータの読み取り | Swift で Sony MakerNote を読む自前パーサーを使う（exiftool には依存しない。開発時の答え合わせにだけ使う） |

## 判定のルール

写真ごとの状態は `未判定` / `採用` / `不採用` の3つ。適用時に次のルールで移動するかどうかを決める。

| 種類 | 未判定 | 採用 | 不採用 |
|---|---|---|---|
| 連写グループのコマ | **移動する** | 残す | 移動する |
| 単写 | 残す | 残す | 移動する |

- 移動するときは、JPG と同じ名前の ARW（拡張子の大文字小文字は区別しない）を一緒に移す
- JPG と ARW のペアは必ずそろって移す。片方の移動に失敗したら、先に移した方を元の場所に戻し、そのペアは移さずに失敗一覧に出す
- 連写グループで1枚も採用しなかったときは、ルールどおり全コマを移す。適用時に警告は出さない

## 連写グループの区切り方

- 連写の判定: `ReleaseMode = Continuous` かつ `SequenceNumber >= 1`
- 写真は撮影時刻（ミリ秒まで）の順に並べる。同じ時刻ならファイル名の順
- 各コマの「連写の先頭番号」を `ファイル番号 − SequenceNumber + 1` で求める。ファイル番号はファイル名の末尾の数字（例: `A1_07866.JPG` → 7866）
- 並び順で隣り合う連写のコマは、連写の先頭番号が同じなら同じグループ、違えば別のグループにする
- 区切った結果、1コマだけになった連写グループは単写として扱う（判定のルールも表示も単写と同じ。未判定なら残す）。選別済みのフォルダで1枚だけ残った連写が、気づかないうちに移るのを防ぐため
- 選別済みで連写の1枚目が抜けているフォルダでも、この方法なら区切れる（例: A1_07866 は3枚目、A1_07868 は5枚目で、どちらも先頭番号は 7864 なので同じグループ。A1_07873 は4枚目で先頭番号が 7870 なので別のグループ）
- 撮影時刻の差では区切らない。連写どうしの間が 0.5 秒ほどしかないことがあり、時刻の差で区切ると別の連写をまとめてしまう
- ファイル名から番号が取れないとき（名前を付け直したファイルなど）は、`SequenceNumber` が 1 のコマ、または前のコマより `SequenceNumber` が小さいか同じコマで区切る

## ARW だけのファイル

ペアの JPG がない ARW も、JPG と同じように表示して選別する。

- プレビューとフィルムストリップのサムネイルの左上に「ARW」マークを付ける
- 判定のルール、連写グループの区切り方、フォーカス位置は JPG と同じ（メタデータは ARW の中の Sony MakerNote から読む）
- 適用すると ARW だけを `_rejected/` に移す
- プレビューとサムネイルは、ARW に埋め込まれた JPEG プレビューを ImageIO で取り出して使う
- 拡大表示（100%・200%）では、ImageIO で RAW を現像して表示する。JPG より表示が遅くなる

## 画面

```
┌──────────────────────────────────────────────┐
│ ツールバー: フォルダ名 / 進捗 (採用n・不採用n・残りn) / [適用] │
├──────────────────────────────────────────────┤
│ [ARW]                                        │
│              大プレビュー（1920）              │
│      Z で 100% → 200% → 全体（本体デコード）     │
│  状態バッジ: 採用 / 不採用 / 連写 3/8          │
│  フォーカス枠 ／ [フォーカス位置へ] ボタン       │
│                                              │
├──────────────────────────────────────────────┤
│ フィルムストリップ（160サムネイル）             │
│ [単][単]|[連1][連2][連3][連4]|[単] ...         │
│ 連写グループは枠と背景色で区切る。採用は緑、不採用は暗く表示 │

```

## 拡大表示

倍率は「全体表示（ウインドウに収める）」「100%（等倍）」「200%」の3段階と、ピンチで変える自由な倍率（全体表示〜200%）がある。

### 操作

| 操作 | 全体表示のとき | 拡大しているとき |
|---|---|---|
| Z | そのコマのフォーカス位置を中心に 100% にする | 100% なら 200% に（今の表示の中心を保つ）、200% なら全体表示に戻す。ピンチで途中の倍率にしているときは、それより大きい段階へ進み、200% 以上なら全体表示に戻す |
| Esc | なし | 全体表示に戻す |
| プレビューをクリック | クリックした点を中心に 100% にする | 全体表示に戻す |
| ドラッグ／2本指スクロール | なし | 表示位置を動かす |
| ピンチ | 指の間の点を中心に拡大する（全体表示〜200% の範囲で自由に変わる） | 同左 |
| F / [フォーカス位置へ] ボタン | そのコマのフォーカス位置を中心に 100% にする（Z と同じ） | そのコマのフォーカス位置に表示位置を移す（倍率は保つ） |

- 一度全体表示に戻してから Z で拡大し直すと、前の位置ではなく、そのときのコマのフォーカス位置を拡大する
- 200% は、100% の画像をそのまま2倍に拡大して描く（別にデコードはしない）

### コマを移ったときの表示位置

| 移り先 | 表示位置 |
|---|---|
| 同じグループの別のコマ | 同じ位置・倍率を保つ（画像上の同じ座標） |
| 別のグループのコマ | 倍率は保ち、移り先のコマのフォーカス位置に移す |

- 単写は1枚で1グループなので、単写から次のコマへ移るときは、移り先のフォーカス位置に移る
- ピンチで変えた途中の倍率も、同じように保つ
- ⌘Z / ⇧⌘Z でコマを戻ったときも、同じルールで表示位置を決める

### フォーカス位置の求め方

- Sony MakerNote の `FocusLocation`（`0x2027`）を使う。値は「画像の幅、高さ、X、Y」の4つ（ピクセル）
- 座標はピクセルのまま使わず、X / 幅、Y / 高さの比率（0〜1）に直してから使う。本体・MPF プレビュー・サムネイルのどれに当てても同じ位置を指せるようにするため
- 座標は回転する前の画素の並び（センサーの向き）で記録されている。縦位置でも幅・高さは横長のまま（例: 8640 4864）。Orientation が 1 以外のときは、画像を回転させるのと同じ変換を比率の座標にもかける（例: Orientation = 8 なら、表示上の座標は (y, 1 − x)）
- 次のときは「フォーカス位置なし」とみなし、画像の中心を使う。枠は描かない
  - `FocusLocation` がない
  - `FocusFrameSize`（`0x2037`）の3番目の値が `0`（枠が無効。MF のときなど）

### フォーカス枠

- `FocusFrameSize` の1番目と2番目（幅、高さ）の大きさの枠を、フォーカス位置を中心に描く。これも幅・高さで割って比率に直す。Orientation が 5〜8（縦位置）のときは幅と高さを入れ替える
- 通常表示と拡大表示のどちらでも描く。⇧F で表示・非表示を切り替える（初期状態は表示）

## 判定後の送り

- P（採用）または X（不採用）を押したら、→ と同じく次のコマへ進む
- 次のコマがすでに判定済みでも飛ばさず、そのコマで止まる
- 連写グループの最後のコマで印を付けたら、次のグループの最初のコマへ進む
- フォルダの最後のコマでは、その場にとどまる
- U（判定の解除）では進まない

## 取り消しとやり直し

- ⌘Z で判定を取り消すと、その判定をしたコマに戻る
- ⇧⌘Z でやり直すと、やり直した判定のコマに移る

## キー操作

| キー | 動作 |
|---|---|
| ← / → | 前 / 次の写真 |
| ↑ / ↓ | 前 / 次のグループ（単写は1枚で1グループとして扱う） |
| P | 採用して次のコマへ |
| X | 不採用にして次のコマへ |
| U | 判定を解除（未判定に戻す） |
| Z | 拡大の切り替え（全体表示 → 100% → 200% → 全体表示。最初はそのコマのフォーカス位置を拡大する） |
| Esc | 全体表示に戻す |
| F | フォーカス位置へ移る（全体表示のときは Z と同じ） |
| ⇧F | フォーカス枠の表示を切り替える |
| ⌘Z / ⇧⌘Z | 判定の取り消し / やり直し（そのコマへ移る） |
| ⌘O | フォルダを開く |
| ⌘, | 設定画面を開く |

マウスでは、プレビューのクリックで拡大を切り替え（クリックした点を 100% に）、拡大中のドラッグで表示位置を動かす。トラックパッドでは、ピンチで拡大・縮小、2本指スクロールで表示位置を動かす。

## 設定画面

| 項目 | 初期値 | 内容 |
|---|---|---|
| 先読み枚数 | 4 | 大プレビューを、今のコマの前後それぞれ何枚先読みするか |

設定は UserDefaults に保存する（フォルダごとではなく、アプリ全体の設定）。

## 適用（一括移動）

1. 「適用」を押すと、移動する枚数（JPG の枚数と ARW の枚数）を確認ダイアログに出す
2. `_rejected/` を作り、JPG と ARW を移す（同じボリュームの中での rename なので速い）
3. 移動した内容を `.photopicker.json` に記録する。「適用を取り消す」で元の場所に戻せるようにする
4. 名前が衝突したときや移動に失敗したときは、そのファイル（ペアなら両方）を飛ばして最後に一覧で報告する

## 速度設計

目標:

- フォルダを開いてからフィルムストリップが出るまで: 5,000 枚で数秒以内
- コマ送り: プリフェッチが効いていれば 1 フレーム（16ms）以内に表示が切り替わる
- 拡大表示: 初回は本体デコード待ちがある。拡大表示中は、グループ内の前後のコマを先読みする

方針:

| 処理 | やり方 |
|---|---|
| メタデータとサムネイル | 各 JPG の先頭（APP1、約44KB）だけを読む。撮影時刻、Orientation、`ReleaseMode`、`SequenceNumber`、`FocusLocation`、`FocusFrameSize`、IFD1 のサムネイル（160×120）を取り出す。複数ファイルを並列で読む |
| 大プレビュー | MPF の2枚目（1920×1080、約100KB）の位置だけを読み、デコードする。今のコマの前後それぞれ N 枚（設定画面の先読み枚数、初期値 4）を先読みし、キャッシュ（NSCache）に置く |
| 拡大表示 | ImageIO で本体をデコードする。拡大表示中だけ、グループ内の前後を先読みする |
| ARW（ペアあり） | 読まない（ペアのファイルがあるかどうかを確認するだけ） |
| ARW だけのファイル | メタデータは ARW の先頭部分（TIFF 構造）から読む。プレビューとサムネイルは埋め込み JPEG を使い、拡大表示のときだけ RAW を現像する |
| キャッシュ | メモリ上だけに持つ。ディスクキャッシュは速度が足りなかったときに検討する |

MPF プレビューが取れない JPG があった場合は、ImageIO の `CGImageSourceCreateThumbnailAtIndex`（長辺 1920）に切り替える。

## 対象外（今回はやらない）

- ★レーティング、カラーラベル、XMP への書き込み
- インターバル撮影の判別とグループ化
- SD カードからの取り込み

## 未決事項

- キャッシュの上限（大プレビューは先読み範囲の前後 N 枚＋表示中のコマを目安に、実測して決める）
- ARW だけのファイルの扱いの細部（ARW のサンプルで構造を調べてから決める）
  - ARW の中の MakerNote から、JPG と同じタグ・値が取れるか
  - 埋め込み JPEG プレビューの大きさ（大プレビューに足りるか）
  - `FocusLocation` の幅・高さが JPG と同じか
- ファイル番号が一周したとき（例: 99999 → 00001）にまたがった連写は、2つのグループに分かれてしまう。まれなので、今は対応しない
