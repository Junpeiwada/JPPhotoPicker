## 概要

JPPhotoPicker を Developer ID 署名・公証した zip として GitHub Release で配布し、Sparkle でアプリ内から更新できるようにする。仕組みは JPScreenShot（`~/Documents/Project/JPScreenShot`）の `release.yml` / `Tools/release.sh` / `UpdaterController.swift` / `Docs/リリース手順.md` をそのまま流用する。リポジトリは 2026-10-05 に公開し、MIT ライセンスにした。

- **対象**: Sparkle の組み込み、更新の確認（起動時・メニューから手動）、タグ push で署名・公証・Release・appcast 更新まで行う CI、手順書、ランディングページ
- **やらないこと**: Mac App Store 配布、App Sandbox 化、DMG 形式（zip のみ）、更新チャネル（ベータ版）の分離、差分更新（delta）
- **関連**: JPScreenShot の [リリース手順.md](../../JPScreenShot/Docs/リリース手順.md) / [release.yml](../../JPScreenShot/.github/workflows/release.yml)

## 注意点

- project.yml の MARKETING_VERSION が既に 0.1.0 なので、初回は 0.1.1 にした（ユーザー判断）

- CFBundleVersion（Sparkle が比較する値）は CI の run 番号で上書きする。手元のビルドの値に頼らない
- 毎回の起動で確認すると、一日に何度も起動したとき通知が繰り返し出る。そうなったら「スキップしたバージョン」で抑えられるので、Sparkle の標準 UI のまま様子を見る
- Debug ビルドでも Sparkle が動くので、開発中に更新ダイアログが出てビルドが上書きされないよう、DEBUG では起動時の確認を止める
- 開発用の署名を Apple Development に固定すると、ビルド環境にその証明書が必要になる
